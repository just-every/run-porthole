# Private dashboards

Open `/app/dashboards` from Explore. Owners, admins and maintainers create a dashboard for a service, team, environment and exact nanosecond range. Each new dashboard contains a selected metric average, log count and trace duration p95. Metric selection is exact; unrelated metrics do not enter the average. Trace durations use milliseconds. Metric units come from intake; incompatible units produce an error.

Add panels and annotations from the dashboard's editor. Keyboard Move up and Move down controls and pointer dragging save a conditional new revision. The JSON editor supports the same validated definition. Clone creates an independent dashboard. Archive preserves the definition and history. Every change uses the current native session and writes a private transactional audit fact.

Team, environment and range controls alter the current view. A private shared link preserves those parameters; it grants no authority. Every opening checks current membership and the complete dashboard scope. Each underlying-query link carries the same signal, service, variables, range, metric selection and completed-ingest watermark into Explore. Historical revisions require both current and historical scope.

Widgets use exact event timestamps and complete resource and point attribute identities, beside their aggregate and source link. Numeric metric panels also accept the bounded ordered rollup, rank, smoothing and counter-rate functions in the existing JSON editor. The current native renderer supports eleven kinds, detailed in `./docs/dashboard-widgets.md`. Previous-week comparisons align samples by exactly seven times 24 hours in UTC, explicitly preserving missing observations instead of interpolating or filling zero; daylight-saving transitions do not change the offset. Both current and previous source links retain their actual ranges. Empty, stale, partial and failed queries have separate labels. Reads follow bounded pages; an unfinished scan has no aggregate presented as complete. TV mode hides editing controls and remains private. Publication is a separate owner-reviewed frozen snapshot, described below.

Installation archives include current dashboards and every saved revision. Restore preserves their definitions but quarantines the current dashboard; an authorized person reviews and saves a new revision before it queries again. Sessions and sharing authority do not transfer.

Explore also accepts a bounded PromQL selector, SQL counts and scalar averages and discrete trace percentiles, and exact Lucene scope terms. Unsupported syntax returns an actionable refusal; the product does not pretend to evaluate full Prometheus expressions. See `./src/porthole/explore/README.md`.

Owners with fresh native proof can preview a deliberately selected numeric snapshot. They manually choose public title and labels, review the exact private source queries, scope, filters, expiry and permitted embed origins, then approve the digest of that exact projection. Signed-out TV, allowed-origin frames and credential-free SVG widget images read only that frozen projection. They never execute anonymous private queries or forward native capabilities. Revocation, expiry, source edits, archive, owner role changes and owner generation changes invalidate all addresses. Installation restore quarantines publications and never restores their authority. Previously downloaded files cannot be recalled; every response is uncacheable. Notes and raw records are not publishable through this numeric snapshot door.

The conservative publication policy awaits ct approval under PORT-018. PORT-068 inherits the explicit publication review and current-authority fences; PORT-035 inherits subject erasure across stored projections. No automatic destruction is introduced.

The complete mandatory widget and function catalog, complete query-language semantics, source-dashboard import parity and twenty-dashboard source corpus remain open contract work. These native widgets and narrow query forms do not qualify the full dashboard catalog.
