# Neighboring products and service evidence

Porthole owns runtime traces, metrics, logs, profiles, APM, infrastructure,
database and RUM performance, and its telemetry spend. A configured handoff is
plain external navigation. It confers no Porthole or destination access, sends
no session credential and never imports a partner result as measured recovery.

Vane owns cookie-free marketing traffic, audiences, goals and funnels. Linen
owns employee IT requests, laptops and CMDB. Evidence owns compliance programs;
Porthole does not certify controls. Vantage or CloudZero owns whole-cloud spend.
Splunk Enterprise Security or Datadog Cloud SIEM owns security analytics, SIEM
and threat response. Datadog CI Visibility handles CI pipeline and test execution;
Datadog Test Optimization handles test optimization; Datadog Data Jobs Monitoring
handles warehouse and Spark data-job operations. Datadog Data Streams Monitoring
or the buyer's selected specialist handles stream-schema and data-quality
analysis. Porthole's runtime messaging throughput, lag and asynchronous trace
context remain distinct from specialist analysis.

## Configure and follow a handoff

Signed-out visitors can read `/help` on the installation without exposing any
configured destination. Signed-in readers open `/app/help` or `/app/integrations`. Owner configuration
is under `/app/settings/integrations/handoffs`, also linked from the existing
Integrations declarations. A current native owner verifies identity within five
minutes and approves the exact destination and current revision. Every revision
has a private audit fact. Non-owner sessions and all bearer writes refuse,
including a bearer accompanied by an owner cookie.

Destinations require HTTPS, without userinfo, control characters, fragments or
credential parameters. An optional same-origin template accepts only `{service}`,
`{environment}`, `{from}` and `{through}` in its path or query. These fields are
explicit declarations; service values are URL encoded and time values are
inclusive original Unix nanoseconds. Help uses the configured base destination;
a runtime service record supplies only the service and environment already
visible to that reader and its current fixed window. No link grants wider
telemetry visibility. A signed-out guide contains no installation destinations.

## Download approved service evidence

From one service record, the native owner selects **Review service evidence
packet**, enters an external system reference and previews the approved field
allowlist: identity, reviewed metadata and revision, observed RED, coverage,
freshness, trace references and log references. Unselected fields are absent.
Raw attributes and log bodies, credentials, other teams' services and partner
job or test results are never packet fields. Missing logs, sampling uncertainty,
partial scans and unavailable telemetry cost remain explicit. No price,
including zero, is invented.

The owner reviews the exact packet and its SHA-256 digest, approves it or
cancels it, then downloads an attachment. The digest covers canonical JSON of
`packet`: recursively sorted object keys and unchanged array order, UTF-8
encoded, without extra whitespace. The enclosing `digest` is not hashed.
Preview, approval and download resolve native service data and current scoped
trace and log readers. Changed metadata, erased inputs, changed authority,
record exclusions, cancellation and changed packet content refuse release.
Only the approving native owner can download; no read credential is designated.
No connector, partner API read or outbound delivery is performed.

An installation archive preserves declarations and packet selection history as
inactive records. It restores neither active handoffs nor export approvals,
source sessions or grants. A destination owner must review a new revision or
create a fresh evidence preview.

## Boundaries still open

Deployment and queue record handoffs await their native domains. The telemetry
cost packet awaits approved usage and rate-card evidence. Evidence-side export
requests, sibling discovery, adapter lifecycle, custody, erasure and retention
holds remain unchanged. This service-only implementation establishes no
provider parity, real estate qualification or complete PORT-054 claim.
