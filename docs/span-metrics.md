# Span metrics and durable sampling

Current scoped native owners preview and approve metric definitions; permitted telemetry readers query and export their scope. Ingest, read and proposal credentials cannot activate definitions. Metric administration and visibility are separate. Future delegated metric administrators remain due under RL-103 in RULINGS.md; PORT-010 inherits this administration boundary under RL-101.

1. POST `/api/porthole/v1/metric-rules/preview` with `definition`, adding existing `id` and `revision` for a change. Inspect the normalized definition, maximum series, scope and USD estimate. The digest binds every definition and cost input, target revision, owner and session for five minutes.
2. POST `/api/porthole/v1/metric-rules/approve` with `previewId`, `digest` and `confirm: "approve-metric-rule"`. Fresh native identity proof from the preceding five minutes is checked at commit. A preview permits one mutation. Changed inputs require another preview.
3. POST `/api/porthole/v1/metric-rules/query` with `id`, `revision`, `from` and `through` for delta aggregates over a half-open nanosecond range. POST the same selection to `/api/porthole/v1/metric-rules/export` for NDJSON containing definition, version, units, temporality, completeness, groups and scoped exemplars. Native readers and current scoped credentials with the metrics signal and telemetry.read action can use these doors. Every request reserves quota and rechecks authority.

Definitions contain `name`, exact `service`, `environment`, `team`, optional `spanName`, `kind`, `value`, `unit`, `dimensions`, `upstream` and `costModel`. Omitting spanName selects all operation names in the exact scope; an explicit name matches verbatim. Kinds are counter, sum and distribution. Counters contribute one per matching span; sums and distributions use any permitted scalar numeric span attribute, or `duration` for original end minus start in nanoseconds. Missing, nonnumeric or out-of-range values disclose incomplete coverage. Per-span sums are bounded to one billion in magnitude and distributions to one trillion. Finite decimal values are supported; sums retain normal IEEE-754 rounding and percentiles use exact nearest ranks. Queries refuse beyond 100,000 points; rule history is bounded to 100 revisions.

Optional `predicate` composes `all` and `any` arrays and `not` with leaves containing `field`, `op` and `value`. Operators are eq, ne, gt, gte, lt, lte, and exists (without value). Numeric comparisons require actual numeric OTLP fields; string and boolean equality retain types. Missing values fail ordinary comparisons. Fields address scalar span attributes, `resource.<key>`, `span.name`, `span.kind`, `span.status`, or `duration`. Expressions allow 32 nodes and depth five. Example:

```json
{"all":[{"field":"invoice.value","op":"gte","value":10},{"field":"region","op":"eq","value":"us"}]}
```

Custom dimensions have explicit permitted values. At most three dimensions, 20 values per dimension and 100 combined series including other buckets are allowed. Fields suggesting credentials or personal identifiers are refused, including auth, token, secret, password, cookie, email, phone, address, user_id, customer_id, SSNs, payment cards and bank accounts. Unlisted actual values enter `[other]` and disclose incompleteness. Forbidden and excessive proposals refuse before approval or billing.

The owner's `costModel` contains source, monthlySpans, bytesPerPoint, usdMicrosPerMillionSpans, usdMicrosPerSeriesMonth, usdMicrosPerGiBMonth and ceilingUsdMicros. Preview rounds compute and storage components upward in microdollars, adds maximum-series cost, and refuses above the ceiling. Include all applicable infrastructure charges in the supplied versioned rates. These are owner projections, never observed provider rates, invoices or permission to purchase. Existing intake and read quotas still apply.

Optional `status: "error"` selects OTLP errors; default is any. `inputStage: "pre-sampling"` selects full-input collection; default accepted uses direct intake. `upstream` must be complete, sampled or unknown: an owner declaration, never independent verification. Empty inputs, matching pending records, reported losses, invalid values and unlisted dimensions remain incomplete. Custom business metrics never borrow Agent RED counts.

Rules apply to subsequently accepted batches. Contributions commit atomically with durable processing before a destination sampling decision can commit. Identity is source credential, signal and explicit batch identity, or exact wire digest when omitted. Identical retry contributes once; changed bytes under the same identity refuse. New explicit identities intentionally count again. Exemplars have only the permitted scope and a timestamp in the selected range; sampled-out traces may have no retained waterfall.

Monitors use the existing object API with `body.signal: "metrics"` and `body.spanMetric: {id, revision, aggregation}`. Aggregations are count, sum, min, max, p50, p95 and p99 across the pinned rule's matching groups. The rule must fit the monitor scope. Normal activation and evaluation apply. Incomplete or erased custom inputs produce Unknown and preserve the previous firing episode, without substituting unrelated RED counts. This bounded threshold integration does not qualify PORT-019's broader catalog.

## Real collectors and destination decisions

`collectors/sampling/collector.yaml` uses official OTel Contrib 0.135.0; `node collectors/sampling/release.mjs` retrieves and checksum-verifies the published Linux x64 archive. Named environment variables provide private destination credentials and listen addresses. The collector forwards synchronously to `/api/porthole/v1/ingest/pre-sampling/traces`, with no acknowledged memory queue, local batch or tail processor. Bounded retry returns failure when delivery fails; the source must retry. Spans never submitted upstream cannot be recovered.

The destination persists each authenticated original envelope, computes custom metrics, then commits sampling and retained copies. Multiple collectors can route siblings independently. Decisions use team, environment and trace ID, independent of collector and credential identity. Explicit defaults retain a deterministic ten percent of ordinary traces and all error or slow whole traces. Scoped native owners preview and approve future revisions at `/api/porthole/v1/sampling/preview` and `/api/porthole/v1/sampling/approve`, using confirm `approve-sampling-policy`. Error protection cannot be disabled.

POST `/api/porthole/v1/red/query` with exact `scope` (team, service and environment), from, through and inputStage for automatic endpoint hits, errors, rates and nearest-rank duration quantiles over accepted spans. The default stage is pre-sampling; direct accepted traffic is a separate population, never added to the same total. Native readers and metrics read credentials are scoped and rechecked. Source-ledger comparison reports pending inputs, missing contributions, invalid durations and loss. The current bounded query refuses beyond 100,000 installation trace inputs. Old completed inputs without reduced points stay explicitly incomplete. Agent statistics are not included.

An error or slow span arriving after an ordinary decision promotes the trace and recovers all accepted siblings while original envelopes remain in custody. Worker and collector restarts preserve destination state and contributions. Configured analytical replicas use a separate ordered retained-projection cursor; a late promotion cannot mutate an immutable source batch or make a lagging replica appear caught up. Reads and failover require both the source and projection watermarks. Retained spans carry policy revision, reason, cohort, probability, weight and promotion time. Upstream completeness stays unknown unless separately qualified. Different service thresholds choose the more protective whole-trace decision.

The declared durable buffer counts pending intake, unfinished decisions and all recoverable full-input original envelopes, including completed decisions. It stays bounded by refusing new input rather than evicting acknowledged protected evidence. A full buffer needs owner-approved capacity or custody maintenance; processing alone does not free original late-span custody. Exhaustion refuses before acknowledgement with Retry-After and an authenticated rejection receipt; acknowledged errors are never evicted. `/api/porthole/v1/sampling/query` reports accepted, pending, intentionally sampled, queryable and archived counts, promotions, loss reasons and completeness by exact scope and half-open time range. `/app/ingest` shows per-source accounting. Pressure and source loss remain visible after later retries recover an error.

Sampling reduces retained trace indexes and retained archive copies. Original full-input envelopes remain in durable custody for late protection and metric provenance. This is not physical raw-storage reduction or PORT-085's horizon qualification. Broader erasure, mixed-subject custody and retention scheduling stay under PORT-035 and PORT-096.

## Agent full-traffic statistics

POST official-schema Datadog Agent StatsPayload JSON to `/api/v0.2/stats` with a current Porthole-scoped metrics ingest credential. Gzip JSON is accepted. The pinned official source is documented in `src/porthole/metrics/agent-stats/schema.ts`; unknown fields and endpoint versions refuse explicitly. Exact unsigned counts and durations remain decimal strings. Endpoint, bucket times, source runtime, sequence and separate successful and error DDSketch bytes survive native custody and restart. GET `/api/porthole/v1/agent-stats` returns scoped paginated deltas independently of sampled traces. Follow every cursor before combining a range. This reader preserves sketches and does not compute their quantiles.

The official-schema edge journey proves PORT-010's distinction between Agent full-traffic statistics and incomplete custom span inputs. Broader transport, compression and real Agent dual-ship parity remain under PORT-062. Source-asserted full traffic is labelled honestly, without claiming independent verification or a live Datadog comparison.

## Custody and qualification

Settings and native archives retain definitions, points and sampling provenance, exclude preview grants, and restore policies quarantined. Restored envelopes cannot grant late-span recovery authority. The first new native input starts a fresh decision when only historical restored inputs exist. New rule evaluation requires a new owner-approved revision. Exact reviewed source erasure removes derived points and local decisions; later journals fence captured replay and older archive restore.

Push Verify invokes the metric focus in `tests/runtime.mjs`: spanMetricJourney, metricPolicyJourney, metricCustodyJourney, agentStatsJourney, samplingJourney and the delivery page at both widths. The separate 10,000-span qualification uses `PORTHOLE_METRIC_SCALE=1 PORTHOLE_METRIC_COLLECTOR=1 PORTHOLE_METRIC_RULES_ONLY=1 node tests/runtime.mjs`, through heavy-slot with a hard timeout. Receipts must name the exact committed SHA. No live Datadog account or production traffic is used.
