# Native service catalog

Open `/app/services` after native sign-in. Discovery reads retained traces within the current service, environment and team scope. Each catalog identity includes all three values. The catalog reports observed versions, per-endpoint request and error counts, rates over the selected absolute time window, and nearest-rank p50, p95 and p99 durations in original nanoseconds. Only server and consumer spans count as requests. Identical trace and span copies contribute once; conflicting identities are omitted and reported. Parent identities establish observed dependencies; missing, conflicting or out-of-scope parents remain unresolved.

The versioned native-session API is `GET /api/porthole/v1/services`, with an optional identity at `GET /api/porthole/v1/services/{id}`. The static OpenAPI artifact describes query bounds and errors. `from` and `through` are inclusive Unix nanoseconds; their defaults select the previous 24 hours. `snapshot` fixes the completed intake watermark. `budget` is 200 through 2000, in multiples of 200. The response marks a truncated scan as partial. This functional slice does not establish upstream completeness: all values are observed retained traffic, never authoritative full-traffic RED. Missing data cannot establish zero full-traffic errors or healthy service state. Freshness is the age of the last retained span: over five minutes is stale. No retained evidence is reported explicitly, even when reviewed metadata remains.

Service configuration is under Settings, linked from the selected service. A current native owner with fresh identity proof reviews the exact assignee, repository, criticality and runbook before saving. `POST /api/porthole/v1/services/{id}` requires the current metadata revision, all reviewed fields and `confirm` equal to `save-service-metadata`. The initial revision is zero. Reassignment requires an existing active member whose current scope covers the service. An empty owner reference explicitly unassigns it. Metadata changes do not alter membership, dataset access or the destination document's permissions. Runbook and repository links require HTTPS and refuse embedded credentials, query strings and fragments. The server never fetches them. External links omit native cookies and referrers.

Every successful change creates an immutable audited revision. Stale revisions, foreign origins, bearer credentials (also with a cookie), forbidden roles and ineligible owners refuse without a metadata change. Current native authority applies again on every read. Queries use the configured analytical worker, with no local fallback when it is unavailable. Final source-record checks prevent erased input from being released as an accumulated catalog result. No detached telemetry aggregate is stored.

Product archives retain exact metadata history as inactive context. Restore quarantines all revisions, creates no source memberships or credentials, and cannot activate ownership authority. A new native owner review is required to replace restored context. Source sessions are never portable.

Datadog full-traffic stats and the identical-window PORT-062 comparison, original SLO comparison, complete infrastructure and database associations, imported repository definitions, default detection, investigation notices and fired-alert metadata continuity remain unproved. This catalog enables no outbound action, monitor, SLO change, erasure or expiry policy.
